### 🥩 Overpass API — 3 грабли при работе с публичным сервером

#### 1. User-Agent обязателен (иначе 406 Not Acceptable)
Публичный сервер `overpass-api.de` отклоняет запросы **без заголовка `User-Agent`** — возвращает 406. Это защита от анонимных ботов. Запросы через `requests` по умолчанию шлют User-Agent вида `python-requests/2.x`, но видимо он не проходит фильтр.

**Решение:** всегда добавлять явный заголовок:
```python
headers = {
    "User-Agent": "ИмяПроекта/1.0 (краткое описание)",
    "Accept": "application/json",
}
requests.post(url, data={"data": query}, headers=headers)
```
Проверено: с этим заголовком статус 200.

#### 2. Публичный сервер часто перегружен (429 и 504)
Главная проблема бесплатного Overpass — лимиты на частоту запросов:
- **429 Too Many Requests** — если слать запросы слишком быстро подряд
- **504 Gateway Timeout** — сервер не успел обработать за отведённое время

**Решение — два приёма вместе:**
1. **Несколько зеркал** с переключением при сбое:
   - `overpass-api.de` (основной, Германия)
   - `overpass.kumi.systems` (резерв)
   - `overpass.openstreetmap.fr` (Франция)
   - `maps.mail.ru/osm/tools/overpass` (Россия — лучше для РФ)
2. **Retry с уважением к `Retry-After`**: при 429 читаем заголовок `Retry-After` (сервер сам говорит, сколько ждать) и повторяем.

#### 3. Объединять несколько запросов в один
Изначально слал два запроса (дома + супермаркеты) — это удваивает шанс нарваться на 429/504. **Объединил в один через union в Overpass QL:**
```
[out:json][timeout:30];
(
  way["building"="residential"](around:R,LAT,LON);
  way["building"="apartments"](around:R,LAT,LON);
  node["shop"="supermarket"](around:R,LAT,LON);
  way["shop"="supermarket"](around:R,LAT,LON);
);
out geom tags;
```
Различаю элементы в ответе по тегам: `building` → дом, `shop=supermarket` → магазин. Один запрос вместо двух = быстрее и надёжнее. Финальная версия использует `out geom tags;` — контуры зданий нужны для подсветки на карте (см. урок ниже).

#### 4. Формат отправки запроса — `data={"data": ...}`
Overpass ждёт поле `data` в form-data, а не «голый» текст в теле. Передача `data=query_text` (без ключа) даёт 406. Правильно: `data={"data": query_text}`.

### 🥩 Gradio 6.0 — миграция с более ранних версий

#### 1. `theme` перенесли из `gr.Blocks()` в `launch()`
В Gradio 6.0 передача `theme=...` в конструктор `gr.Blocks(theme=...)` вызывает UserWarning и игнорируется. Тему надо передавать в `demo.launch(theme=...)`. Обнаружено по предупреждению в логах при импорте.

### 🥩 Python на macOS с Homebrew — несколько версий

В системе было сразу 4 версии Python: системный 3.8 (устаревший), и через Homebrew — 3.11, 3.13, 3.14. Для современных библиотек (Gradio, FastAPI) лучше брать **3.11** — проверенная, со всеми пакетами. 3.14 слишком свежая (некоторые пакеты могут не иметь колёс).

Создать venv на конкретной версии: `/opt/homebrew/bin/python3.11 -m venv venv`.

### 🥩 Интерактивная карта с выбором точки (Gradio 6.23 + folium 0.20)

Задача: клик по карте → подставить координаты в поля. Грабли и решения:

#### 1. gr.Map в Gradio 6.23 НЕТ
`hasattr(gr, 'Map')` → False. Компонент убрали из новых версий. Выход: folium-карта в `gr.HTML` + JS-мост через собственный FastAPI-эндпоинт.

#### 2. Скрипты folium вставляются ДО создания карты
`m.get_root().script.add_child(js)` кладёт скрипт РАНЬШЕ `var map_xxx = L.map(...)` — выполнение падает с «Cannot read properties of undefined». **Решение:** обернуть в проверку `typeof map_xxx !== 'undefined'` с `setTimeout(init, 300)`.

#### 3. gr.HTML не знает высоту своего iframe
Без явного `height=` карта схлопывается и перекрывается соседними элементами (клик не работает). **Решение:** `gr.HTML(value=..., height=420)`.

#### 4. Два iframe = две проблемы для теста
Gradio оборачивает gr.HTML в iframe (srcdoc), folium — ещё в один. Playwright-клики по геометрии вложенных фреймов ненадёжны; надёжный тест — `dispatchEvent(new MouseEvent('click', {clientX, clientY}))` прямо во фрейме карты.

#### 5. demo.launch() не поднимает FastAPI-эндпоинты
Gradio-запуск работает без FastAPI-роутов (мой /set_point → 404). **Решение:** запуск через `uvicorn.run(app, ...)`, а тему передавать в `gr.mount_gradio_app(theme=...)` (в 6.23 параметр есть).

#### 6. pkill -f "python app.py" не убивает "Python app.py"
Регистр букв! `pkill` case-sensitive: процесс называется `Python app.py` (заглавная P из Homebrew). Старый сервер переживал перезапуск и продолжал отдавать старый код. **Решение:** убивать по PID: `lsof -ti :7860 -sTCP:LISTEN | xargs kill`.

### 🥩 Подсветка зданий на карте — out geom вместо out center

Задача: раскрасить каждый жилой дом по этажности. Грабли:

#### 1. out center отдаёт только центр, контуров нет
Для отрисовки полигонов зданий нужен `out geom tags;` — он добавляет каждому way/relation поле `geometry` (список `{lat, lon}` точек контура). Проверено на реальном запросе: 115 из 116 зданий пришли с контурами (у одного нет geometry — запасной вариант: CircleMarker в центре).

#### 2. Единая классификация этажности — для счёта И цвета
Логика «1-3 / 4-9 / 10+ / неизвестно» раньше жила внутри функции подсчёта. Для карты нужна та же классификация — вынес в `classify_building_levels()`. Одна правка в границах — обновятся и отчёт, и карта.

#### 3. Легенда на folium — обычный HTML-элемент
`position:fixed` в folium-iframe работает (iframe — это отдельный viewport). Легенда: `m.get_root().html.add_child(folium.Element(html))`.

#### 4. Проверка полигонов в Playwright
После анализа в фрейме карты появляются SVG-пути: `document.querySelectorAll('.leaflet-overlay-pane path').length` — должно быть ~равно числу зданий (116). Это удобный индикатор, что подсветка на месте.
